# 模型配置手册

本文说明当前 Prism 运维台的模型配置流程。配置直接写入活动目录，保存成功后由下一次请求读取；不需要配置历史、草稿、发布、证明、激活或部署代次。

## 1. 配置边界

运维人员维护五类信息：

| 对象 | 内容 |
|---|---|
| 模型 | 对外模型名、显示名、类型和可见性 |
| 服务规格 | 操作、服务等级、变体和下游入口 |
| 上游 | 渠道、上游模型名、请求端点和 Adapter |
| 映射 | 参数约束及上下游 JSON 字段映射 |
| 商业配置 | 调用价格、可选上游成本、路由优先级、权重和 API Key |

一次请求开始时读取一份完整配置，执行期间不再重新读取。编辑只影响保存成功后开始的新请求。

## 2. 准备信息

配置前确认：

- 上游 API 文档，包括鉴权、请求路径、请求字段、响应字段和异步查询方式；
- 对外模型名与上游真实模型名；
- 模型类型：LLM、图片或视频；
- 上游渠道、Base URL 和 API Key；
- 调用价格和计费单位；上游成本仅在有可靠资料时记录；
- 下游需要开放的 Prism API 路径。

不要把价格或 API Key 写入映射 JSON。价格由费率配置管理，Key 由凭据池管理。

## 3. 直接配置流程

1. 打开“运维台 > 上游网关”，按 LLM、图片或视频筛选网关。
2. 打开网关详情，在“上游 Key”点击“添加 API Key”。默认同时建立独立分组，无需先建 Key 池；该分组不继承其他 Key 的模型或价格。
3. 进入“模型与映射”，点击“接入模型”。
4. 选择 Key 池、接入格式和对外模型，填写上游模型名、地址、路径及 JSON 映射。
5. 保存后在同一页核对“上游模型 → 对外模型”关系；需要更改时点击该上游模型的编辑按钮。
6. 进入“模型”视图核对调用价格、下游入口和线路优先级。新建模型必须填写调用价格，接入表单不要求填写成本；上游报价仅供参考，不自动写入价格。
7. 发起一笔真实的最小请求，在“调用记录”中检查路由、上游响应和计费结果。

页面会携带当前 `config_version` 防止并发覆盖。若提示配置已更新，刷新详情后重新提交；不要绕过版本检查。

“接入模型”对新模型使用一次性原子写入：同时创建对外模型、服务规格、上游 Transport、Key 池关系、路由和调用费率。保存失败时整笔回滚，成功后只增加一次 `config_version`。接口为 `POST /api/admin/unified-gateway/catalog-changes/model-onboard`；`sell_rate` 必填，`cost_rate` 可省略，金额使用当前结算币种。省略成本时不建立成本费率、不生成估算成本事件，不能当作零成本。运维人员不需要先建立价格证据或走发布流程。

保存报错显示在固定底部的保存按钮附近；字段校验失败同时显示就地错误，并滚动、聚焦对应字段。

## 4. 按模型类型配置

### LLM

根据上游协议选择 Adapter，例如 OpenAI Chat、OpenAI Responses、Anthropic Messages 或 Google Generate Content。重点核对：

- 下游入口与操作类型匹配；
- 上游模型名正确；
- 流式与非流式响应都符合所选 Adapter；
- 按 Token 计费时直接填写输入、输出、缓存读取、缓存写入四项价格，单位为当前结算币种／百万 Token；输入、输出必填，缓存读写可留空，填写 `0` 表示该项免费。
- 缓存价格留空时沿用输入价格；单独填写后从普通输入中扣除对应用量，避免重复计费。上游未提供缓存写入用量时不能配置独立缓存写入费率。
- 输入／输出 Token 预留上限为最多 18 位的正整数，用于调用前预留余额，不限制上游请求；最终按实际用量结算。分项上限分别预留，余额预留可能高于最终费用。

### 图片

核对生成或编辑入口、图片尺寸、张数、质量等参数约束。调用价格按实际计费单位配置；成本可不记录，不写入映射 JSON。

### 视频

视频的 JSON 指上下游关系映射，不代表视频只能使用某种固定请求格式。映射应明确：

- 创建任务时各字段从下游 JSON 写到上游 JSON 的位置；
- 上游任务 ID、状态、进度、结果 URL 和错误字段的读取位置；
- 轮询路径、间隔和终态；
- 上游支持回调时的回调字段与认证方式；
- 分辨率、时长、比例等参数约束。

使用固定 Adapter 时只配置其开放字段；使用 Generic Video 时按 Adapter Manifest 填写完整映射。不要凭经验猜字段路径。

## 5. API Key

新建和替换的上游 API Key 明文保存在 `gw_credentials.secret`。这是当前接受的存储方案。

- 新建 Key 默认通过 `POST /api/admin/unified-gateway/channels/:id/credentials` 原子创建独立分组和 Key，返回 `id` 与 `pool_id`。失败时全部回滚，不留下空分组。
- 不同价格、权限或服务规格的 Key 分开接入；新分组不自动关联已有模型，也不修改已有 Key、模型或价格。
- 只有确认价格、权限和服务规格一致时，才勾选“加入当前分组”。这时使用原有 `POST /api/admin/unified-gateway/pools/:id/credentials` 接口，继承该分组已配置的模型线路。

- 写入接口接收完整 Key；
- 读取接口不返回 Key，也不生成可还原的展示值；
- 调用日志和审计记录不保存 Key 内容；
- 替换或停用后无需发布，下一次请求使用新状态；
- 旧加密凭据仍可在迁移期间读取，替换后改用明文列。

`PRISM_GATEWAY_PAYLOAD_KEK_B64` 与 `PRISM_GATEWAY_PAYLOAD_HMAC_B64` 始终用于请求、结果和回调资料。只有数据库仍包含需要读取的旧加密凭据时，才需要保留 `PRISM_GATEWAY_KEK_B64` 与 `PRISM_GATEWAY_HMAC_B64`。

### 模型列表快照

这里的快照只是一次上游模型列表的记录，不是数据库备份，也不是配置草稿或发布步骤。

在“上游 Key”选中一个 Key，点击“模型列表与拉取”。首次配置会从当前 Key 的线路或分组带入唯一的已知上游地址；新分组可使用当前渠道的唯一地址。多地址时保留选择，地址前缀为标准 `/v1` 时只带入域名。选择“新建拉取配置”会带入当前已保存配置的地址、分组、协议和超时。核对后点击“保存配置并拉取”；已有配置直接点击“拉取最新”。历史列表可分页查看，模型名搜索只查询保存的快照。

- 首次配置接口为 `POST /api/admin/unified-gateway/credentials/:id/catalog-source`，字段是 `base_url`、`external_group`、`request_timeout_ms`、`protocol_definition_id`。事务内明确授权此 Key 的 `catalog_discovery` 用途并保存来源；相同 Key、协议、地址、分组及超时的配置复用原来源，不继承其他 Key 的来源。配置保存失败时授权一起回滚。
- 没有上游分组的标准模型列表使用 `default`。默认协议为数据库里的 `standard_model_catalog`：Bearer 鉴权、`GET /v1/models`、`data[].id`。地址只填协议与域名，其他列表路径和鉴权方式在协议配置中维护；不会自动选择其他上游的登录协议。
- 活动目录新增 `POST /api/admin/unified-gateway/catalog/:id/catalog-sources/:source_id/refresh`，请求正文为 `{}`。仅安排只读拉取，不创建、启用、停用或合并模型，不修改价格与路由。
- 发现来源必须绑定实际 Key、有效的 `catalog_discovery` 授权及数据库协议配置。Key、渠道或分组不可用时不发起请求；排队期间 Key 被替换、撤销或过期时，任务失败，不改用其他 Key。
- 同一来源有排队或执行中的拉取时返回该运行 ID，不再新建运行；完成或失败后再次手动拉取会建立新运行和新快照，不覆盖历史列表。
- 历史列表 `GET /api/admin/unified-gateway/catalog/:id/discoveries` 支持 `source_id` 和 `credential_id` 筛选；按运行使用的实际 Key 筛选，不把同池的其他 Key 混入。
- 查看 `GET /api/admin/unified-gateway/catalog-discoveries/:snapshot_id/items` 只读取 Prism 已保存的列表，不访问上游；`q` 按模型名搜索，价格原始字段及倍率原样保存。合法的空列表也保存；缺失列表字段仍判为错误。未返回的价格和能力保持未知，不补成零。
- “补全接入”进入新建公开模型表单，仅带入实际上游模型名、地址及该 Key 所属分组；不复制原文描述到公开介绍，也不把未经核实的价格与能力直接启用。公开名、价格与能力仍需填写。
- 旧 `/discover` 接口保留给原有草稿流程；日常 Key 拉取使用新增 `/refresh` 接口。

部署前需执行 `database/migrations/20261010_190000_repeatable_catalog_snapshots.sql`。它仅把“同一来源最多一个快照”的唯一索引改为普通索引，保留“每个运行最多一个快照”的唯一限制，不改现有数据。

`database/migrations/20261010_191000_standard_model_catalog_protocol.sql` 新增通用模型列表协议，不含上游地址或凭据，不覆盖已有协议配置。读取和执行始终使用数据库定义，不在执行器里写厂商专用路径。

目前已完成拉取页面、首次来源配置、已有 Key 的模型发现授权、快照搜索、候选模型选择、公开名称冲突处理、Token 价格表单、LLM 能力表单和 Key 移除；尚未部署或执行迁移。快照结果不会提前自动上架。

### 独立公开名称

- 接入表单默认“新建公开模型”，不因上游模型同名而关联已有模型。快照候选自动读取一个独立名称建议；手动接入使用“生成独立名称”。
- `GET /api/admin/unified-gateway/model-name-suggestion?base_name=a` 只查 Prism 全局模型名与模型标识。`a` 可用时使用 `a`；否则依次建议 `a-2`、`a-3`。不添加上游名称前缀，不访问上游，不占用名称。
- 停用、隐藏模型及旧目录中的名称同样视为已占用；比较使用数据库唯一索引的规则。最多尝试 100 个名称；超出时需手动更换公开名。后缀计入 128 UTF-8 字节上限，必要时只缩短公开名。
- 保存“新建公开模型”时在事务内新建身份；名称或模型标识已存在即返回 409。并发占用同样拒绝并回滚，不自动合并、改名或改用其他 Key。原有 SKU 创建和编辑接口保持原行为。
- `sku.api_name` / `sku.model_code` 是独立公开身份；`product.vendor_model` 始终是实际发给上游的名称。不同 Key 对应各自的池、模型和费率。
- 明确选择“关联已有模型”时，必须勾选价格、权限和服务规格一致；改变所选分组、Adapter 或模型会取消该确认。
- 本阶段不变更真实数据库，不增加迁移，不改变查价系数、现有绑定或视频执行流程。

### LLM Token 计费

- 新建 LLM 模型可选择“按输入 / 输出 Token”；表单分别填写输入、输出的售价与成本，以及两者各自的计费上限。
- 价格单位固定为“每百万 Token”，写入现有费率结构：`unit_code=token`、`unit_scale=6`、`quantity_source=usage.input_tokens` 或 `usage.output_tokens`。输入和输出是两条独立费率，不混在一条表达式里。
- 上限只用于请求前的金额预留；实际结算读取 Adapter 产生的 usage。缺少 usage 不会按零收费，而是保持未知并失败，避免少收费用。
- 本功能不改变下游请求字段，也不凭模型名称猜上下文窗口；上下文限制仍由 Adapter 与上游返回负责。未知的 Token 价格或上限不能自动填零。
- 旧的按次、按秒模型请求格式和费率保持不变；Token 费率会在同一模型接入事务中原子写入，任何一条失败都会全部回滚。
- `sell_rate` / `cost_rate` 保留为主费率（输入）；输出通过新增的 `additional_sell_rates` / `additional_cost_rates` 写入。接口同时返回全部 `sell_rate_ids` / `cost_rate_ids`，原有单个 ID 字段保持兼容。每份售价或成本最多 32 条组件，重复代码、重复计量和缓存重复计费会在写入前拒绝。
- 此阶段复用已有 Token 计费表，不增加迁移。管理表单填写原始配置单价；查价乘 1.8、页面与估价总额截两位、API 精确单价保留的规则继续沿用。

### LLM 能力字段

- 新建 LLM 模型提供上下文上限、流式、工具、图像、音频和推理能力字段。所有字段可留空；未填写或未勾选表示未知，不表示不支持。
- 已填写内容写入 `product.capability_constraints.llm`，例如 `context_window`、`supports_tools`。这只是结构化描述，不会凭空限制请求，也不会改变 Adapter 的下游 JSON。
- 只有文档或上游明确给出的能力才填写；不确定项保持未知，避免模型详情把缺失字段解释为零或不支持。
- `/v1/models/:code` 仅返回所有可执行线路都一致的 `llm_options`；冲突或缺失字段不返回，明确的 `false` 会保留。`/v1/models` 只返回摘要。只投影白名单字段，不返回映射、上游地址或供应商字段。

### Key 移除

- `POST /api/admin/unified-gateway/credentials/:id/remove` 使用 `expected_version` 执行移除。第一次调用立即进入 `draining`，不再接收新请求并停用绑定的可用性来源；已有调用、异步任务、目录拉取和结果交付全部结束后，刷新预览并再次确认完成移除，进入 `disabled` 并清除明文及旧密文。没有进行中任务时一次完成。
- `GET /api/admin/unified-gateway/credentials/:id/removal-impact` 可先查看进行中调用、控制任务、待交付结果、其他可用 Key 和受影响模型。移除不会删除模型配置、公开名、价格、账务或历史审计；没有其他可用 Key 的线路会停用，并可单独恢复或重新接入。
- 后端按当前目录重新检查影响，拒绝旧 `expected_version`；并发冲突或清除失败时整个事务回滚。`terminated_unknown`、目录 `manual_review` 和排队中的结果交付同样阻止清除。原“完成停用”接口也不能绕过这些检查。
- 移除期间保留原 Key 供既有任务查询和交付；不替换既有任务的凭据。新请求停止选择这个 Key，独立分组不会自动借用其他分组的 Key。
- 当前界面保留已移除 Key 的状态和管理入口，便于核对影响及历史；显示停用状态，不显示密钥内容。完全清除的 Key 可用新标识重新添加，新建分组不自动恢复原模型线路。

## 6. 保存与验证

每次保存应满足：

1. 数据库事务成功；
2. `config_version` 增加；
3. 审计记录包含操作者、对象和修改字段，但不包含 Key；
4. 下一次新请求读取修改后的配置；
5. 已开始的请求继续使用开始时固定的配置。

最小验收至少覆盖：

- LLM：一次非流式请求；
- 图片：一次生成或编辑请求；
- 视频：一次创建及轮询到终态；
- Key：替换后新请求成功，停用后不再被选择；
- 计费：调用价格与实际用量、调用记录一致；已配置成本时另行核对。

## 7. 故障定位

| 现象 | 首先检查 |
|---|---|
| 模型不可用 | 下游入口、可见性、Offering 运行状态 |
| 没有可用上游 | 路由、凭据池、Key 状态、并发限制 |
| 上游返回参数错误 | Adapter、上游模型名、映射 JSON |
| 视频一直处理中 | 任务 ID 映射、轮询路径、状态与终态映射 |
| 金额不正确 | 售价、成本、计费单位及表达式 |
| 保存冲突 | 刷新详情，使用新的 `config_version` 重试 |

调用问题以“调用记录”中的 Call、Attempt 和上游请求日志为准；配置修改以审计记录为准。
