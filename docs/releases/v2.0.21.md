# Prism 2.0.21

Video task tracking now supports continued recovery and manual resumption when an upstream task identity or result needs repair. Channel-specific onboarding data is excluded from the release source.

The public migration lineage now starts from a clean schema baseline. New installations do not receive private provider channels, credentials, pricing, or mappings.

## Required upgrade procedure

This release requires a manual transition for existing databases. Console automatic installation rejects an unadopted legacy database before stopping the service or changing data.

Back up the database and installed executable, stop application traffic, then run the new executable with `migrate rebase` followed by `migrate up`. Start the new executable only after both commands succeed. See [migration baseline instructions](../MIGRATION_BASELINE.md) for supported checkpoints and validation requirements.

Do not restore an older executable against an adopted database. A rollback requires restoring the matching database backup as well.

## Validation

Go unit tests, vet, frontend type checking, frontend build, 151 frontend tests, and the local isolated MySQL migration integration suite passed. Fresh installation and both supported legacy checkpoints were verified, including unchanged application data and rejection of dirty history and schema drift.
