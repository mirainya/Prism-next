## 管理行为

- 添加 Key 默认创建独立分组。使用已有分组必须确认价格、权限和规格一致。
- 管理员显式拉取 Key 的模型列表；搜索、翻页和查看历史读取本地快照。历史快照保留，合法空列表不会自动停用模型。
- 新接入的模型使用独立公开名；同名时建议增加数字后缀，上游调用继续使用实际模型名。
- LLM 输入、输出价格分别按每百万 Token 配置，保留精确字符串。查价系数继续使用现有配置。
- LLM 能力可配置上下文、流式、工具、视觉、音频及推理。未知字段不补零或 false；公开 `llm_options` 仅包含所有可执行线路一致的已知字段。
- 移除 Key 前展示影响；先停止新调用，待调用、控制任务及结果交付完成后才能清除秘密。存在在途任务时须刷新并再次完成移除。
- Key 清除后保留身份、模型、价格、账务和审计。完全清除的 Key 可使用新标识重新添加，旧模型线路不会自动恢复。

接口与详细步骤见 [模型接入与 Key 管理](../MODEL_ONBOARDING.md)。

## 数据库变更

用户确认后通过迁移管理器应用以下两份迁移，并登记校验值：

- `20261010_190000_repeatable_catalog_snapshots.sql`：来源索引改为普通索引，继续保留每次运行的唯一限制与历史记录。
- `20261010_191000_standard_model_catalog_protocol.sql`：新增标准 Bearer `/v1/models` 发现协议，HTTP 执行信息来自数据库配置。

完整 SQL、旧程序、运行配置及受影响表的备份保存在私有发布目录。迁移应用后，旧程序不能直接回退启动，恢复时须同时核对迁移历史与保留的数据。
